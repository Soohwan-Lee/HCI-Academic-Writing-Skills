# HCI Academic Writing Skills

**연구 근거를 설득력 있는 HCI 논문의 논증으로 연결합니다.**

기존 ACM LaTeX 프로젝트에서 HCI 논문을 쓰는 연구자를 위한 에이전트 스킬입니다. AI 코딩 에이전트에게 라이팅 작업과 연구 근거를 제공하면, 스킬의 지침에 따라 에이전트가 논문의 기여를 파악하고 관련 `.tex` 파일을 직접 수정한 뒤 변경 내용과 아직 필요한 근거를 보고합니다.

## 논문 폴더에서 하는 일

설치기는 스킬 폴더를 프로젝트에 복사합니다. 이 폴더에는 지침, 라이팅 참고 자료, 읽기 전용 LaTeX 검사 스크립트가 들어 있습니다. 원고 파일의 위치는 그대로입니다. 여러 파일로 나뉜 프로젝트는 다음과 같은 형태일 수 있습니다.

```text
my-paper/
├── chi26.tex                          # 루트 파일
├── sections/related-work.tex          # 수정을 요청할 파일
├── sections/...                       # 다른 섹션
└── .claude/skills/hci-academic-writing/   # 설치된 스킬(Claude Code)
```

범위가 정해진 요청을 받으면 스킬은 에이전트가 다음 순서로 작업하도록 안내합니다.

1. **작업 파악:** 요청한 결과물, 목표 학회나 트랙, 연구 단계, 사용 가능한 근거, 루트 `.tex`, 수정 범위를 확인합니다. 논증을 바꾸는 정보가 빠졌을 때만 질문하고, 그동안 근거가 있는 작업은 계속합니다.
2. **필요한 부분 읽기:** 해당 섹션과 의존 파일, 작업에 필요한 지침만 읽습니다. 문단 하나를 다듬는 데 프로젝트 전체 사전 조사를 요구하지 않습니다.
3. **원고 수정:** 편집 보고서만 내지 않고 기존 파일에 요청한 변경을 반영합니다.
4. **근거 공백 표시:** 알 수 없는 사실은 빼거나, 빠진 명제 전체를 `% HCI-TODO[evidence]: verify the condition contrast` 같은 주석으로 남깁니다.
5. **확인과 보고:** diff와 관련 참고 자료를 확인한 뒤, 무엇을 바꾸고 확인했는지, 어떤 근거가 더 필요한지 보고합니다.

### 요청에 포함하면 좋은 정보

- 루트 `.tex`와 작업할 파일, 섹션 또는 문단
- 작업 내용과 목표 단어 수 같은 제한 조건
- 연구 근거: 결과, 분석 노트, 연구 세부 사항, 디자인 기록 등
- 학회별 요건을 다루는 작업이라면 목표 학회·트랙과 템플릿 또는 공식 CFP
- 컴파일이 필요한 경우 TeX 환경

### 수정되는 것

에이전트는 지정한 범위 안에서 원고 본문을 수정합니다. 이 작업 흐름은 프로젝트 구조, 매크로, BibTeX 키, label과 무관한 수정을 보존합니다. 표현만 다듬을 때는 기존 주장과 인용의 연결을 유지합니다.

스킬은 연구, 참여자, 인용문, 통계, 참고문헌, 원문을 읽었다는 주장을 지어내지 않도록 지시합니다. 다만 지침이 실제 동작을 보장하지는 않으므로 모든 변경을 직접 검토하세요([검증 결과와 한계](#검증-결과와-한계) 참고).

함께 제공되는 검사기는 LaTeX의 정적 의존성을 확인하며 파일을 수정하지 않습니다. 실제 컴파일에는 TeX 환경이 필요합니다. Overleaf 업로드와 제출은 별도 작업입니다. ACM 템플릿 자체를 포함하거나 대체하지 않습니다.

## 작업 결과 예시

아래 예시는 각 요청이 지향하는 결과를 보여 줍니다. 측정된 개선 효과가 아닙니다.

| 작업 전 | 요청한 결과 |
|---|---|
| Related work가 저자별 문단으로 나열됨 | 미해결 문제를 중심으로 구성하고, 기존 주장과 인용의 연결을 유지하며, 실질적인 근거 공백을 표시 |
| 집단 의사결정 논문에서 시스템 기여와 발견이 섞여 있음 | 제공한 결과로 둘을 구분한 개요를 만들고, 집단 결과를 개인 판단에 관한 주장으로 바꾸지 않음 |
| 가정용 오브제 디자인 연구가 활동 나열에 머묾 | 제작과 성찰이 디자인 지식으로 이어지는 과정을 정리하고, 모호함과 상반된 해석을 유지하며, 효과 검증을 지어내지 않음 |
| 결과 문단이 분량을 초과함 | 기존 `.tex`를 150단어로 압축하되 효과 추정치, 불확실성, 유의하지 않은 결과, 분석 단위를 유지하고, 단어 집계 기준과 주요 변경을 보고 |
| 아직 데이터 수집을 시작하지 않음 | 연구 동기, related work, 실제 방법을 작성하고, 계획 단계임을 드러내는 표현을 유지하며, 결과에 따라 달라질 내용은 가상의 발견 대신 초안 주석으로 남김 |

## 시작하기

**1. 논문 프로젝트에 설치합니다.** Python 3.9 이상이면 충분하며 별도 Python 패키지는 필요 없습니다. 이 저장소의 루트에서 실행하고, `/path/to/paper`는 기존 논문 프로젝트 경로로 바꾸세요.

```sh
git clone https://github.com/Soohwan-Lee/HCI-Academic-Writing-Skills.git
cd HCI-Academic-Writing-Skills

# 미리보기: 파일을 생성하지 않습니다.
python3 scripts/install_skill.py --host codex --scope project --project-root /path/to/paper

# 전체 스킬 폴더를 복사합니다.
python3 scripts/install_skill.py --host codex --scope project --project-root /path/to/paper --apply
```

Claude Code는 `--host claude-code`, Antigravity는 사용 환경에 맞게 `--host antigravity-app`, `antigravity-ide`, `antigravity-cli`를 선택합니다.

설치기는 내용이 다른 기존 파일을 덮어쓰지 않습니다. 업데이트할 때는 이전 설치본을 검토하고 옮긴 뒤 설치하세요. 전역 설정은 변경하지 않습니다. [개인용 설치·호스트별 경로·호환성 근거](docs/COMPATIBILITY.md)를 참고하세요.

**2. 논문 프로젝트에서 새 에이전트 세션을 엽니다.** `hci-academic-writing` 사용을 명시적으로 요청하고, 에이전트가 의도한 `SKILL.md`를 읽는지 확인하세요. 핵심 스킬은 독립적으로 사용할 수 있으며, 연결된 공개 논문 분석은 필요할 때 추가로 읽습니다.

**3. 범위가 작은 작업부터 시작합니다.** 예를 들면:

> hci-academic-writing을 사용해줘. 루트는 chi26.tex야.
> sections/related-work.tex를 저자별 나열에서 미해결 문제 중심의 논증으로
> 다듬어줘. 기존 주장과 인용의 연결은 유지하고, 문단 간 흐름과 문장 연결을
> 개선해줘. 실질적으로 근거가 부족한 부분만 표시해줘.

> hci-academic-writing을 사용해서 결과 문단을 150단어로 압축해줘. 효과 추정치,
> 불확실성, 유의하지 않은 결과, 분석 단위를 유지하고 기존 .tex를 수정해줘.
> 단어 집계 기준과 주요 변경을 알려줘.

### 호스트 호환성

| 호스트 | 문서상 경로·형식 | 설치 | 실제 원고 편집 |
|---|---|---|---|
| Claude Code | 확인함 | 격리된 임시 디렉터리에서 테스트 | 격리된 ACM 편집 작업 2건, 스킬 이름을 명시해 로드 |
| Codex | 확인함 | 격리된 임시 디렉터리에서 테스트 | 테스트하지 않음 |
| Antigravity | 확인함 | 격리된 임시 디렉터리에서 테스트 | 테스트하지 않음 |

자동 탐색 여부는 아직 검증하지 않았습니다. 테스트한 제한적 Claude Code 구성에서는 slash 호출도 검증되지 않았습니다.

## 기여는 방법, 주제, 학회와 다릅니다

기여(contribution)는 논문이 제시하는 지식의 변화입니다. 독자가 논문을 읽은 뒤 무엇을 이해하고, 만들고, 실행하고, 다시 생각해야 하는지, 그리고 어떤 근거가 그 변화를 뒷받침하는지를 뜻합니다. 스킬은 다음 항목을 각각 별도의 선택으로 다룹니다.

| 선택 | 답하는 질문 | 가상의 예 |
|---|---|---|
| 기여 | 독자가 무엇을 얻고, 왜 받아들여야 하는가? | 새로운 인터랙션 기능 |
| 방법 | 근거를 어떻게 만들었는가? | 사용자 연구 |
| 주제 | 무엇에 관한 논문인가? | 집단 의사결정 |
| 학회 | 어디에 제출하는가? | CHI |
| 논문 형식 | 논증을 어떤 형태로 제시하는가? | 일반 논문 또는 pictorial |

시스템을 평가하기 위해 연구를 수행했다고 해서 논문이 자동으로 경험 연구 중심이 되지는 않습니다. 이런 평가는 대개 시스템·기법 경로 안에 머뭅니다. 두 가지 실질적 주장에 서로 다른 논거가 필요하면 hybrid 경로를 사용합니다.

지식 기여를 파악한 뒤 다음 작성·근거 지침을 선택합니다.

| 기여 유형 | 주요 라이팅 과제 |
|---|---|
| 정량적 발견 | 구성개념, 비교, 분석 단위, 불확실성과 추론 범위 |
| 정성적 이해 | 맥락 속 경험, 해석, 성찰성과 분석적 기여 |
| 시스템·인터랙션 기법 | 새로운 기능, 작동 원리, 평가 질문과 실패 조건 |
| 디자인·Research through Design | 제작, 물성과의 만남, 성찰과 디자인 지식 |
| 개념·이론 | 전제, 구분, 설명력과 적용 한계 |
| 방법·도구 | 절차, 근거, 타당성과 사용 조건 |
| 데이터셋·리소스 | 출처, 구축, 특성, 재사용과 관리 |
| 리뷰·문헌 종합 | 선정 과정, 코딩 단위, 종합과 리뷰 유형별 요건 |

복합 기여에는 여러 경로를 함께 적용합니다. Pictorial은 시각적 논증과 읽기 경로를 유지합니다. 공통 모듈은 abstract, introduction, 연구 공백을 중심으로 한 related work, 문단의 역할, 문장 간 연결, discussion, 압축, 리뷰어 응답을 다룹니다. 8,000단어 배분표는 **편집용 출발점**이며 측정으로 입증된 표준이 아닙니다.

[기여 선택 안내](skills/hci-academic-writing/references/contribution-catalogue.md)는 사회기술적 이해, 이론 적용·수정, 비판, 참여를 통한 변화, 역사 연구, 재현 연구 등을 세분화하고 근거에 맞는 작성 지침으로 연결합니다. [사회기술적 분석 지침](skills/hci-academic-writing/references/sociotechnical.md)은 관계, 분석 수준, 해석적 문단 흐름을 다룹니다. 일부 세부 유형은 직접 분석한 대표 사례가 부족하며, 추가 분석에서 보완할 예정입니다.

## 확인할 수 있는 근거

**전문 기반 분석 112편:** CHI 38편, CSCW 22편, UIST 15편, DIS 18편, IUI 17편으로 5개 학회 110편이며, COMPASS와 Findings of EMNLP 각 1편이 보충 사례입니다. 수상작, 주요 연구 흐름과 방법론적 대조 사례를 포함합니다. 수상 여부는 별도로 확인하며, 명성을 라이팅 규칙의 근거로 삼지 않습니다.

협업, 인간–AI 상호작용, 반대 의견과 성찰뿐 아니라 접근성, 프라이버시, 돌봄, 교육, 공예, 신체적 인터랙션과 사회적 맥락의 연구를 함께 다룹니다. 목적 표집한 교육용 사례집이며 대표 표본은 아닙니다. 시스템 논문의 비중이 높고, 일부 경로는 추가 확충이 필요합니다.

**완료가 아닌 계획:** [100편 추가 분석](docs/EXPANSION-200.md)을 계획하고 있으며 목표는 총 208편입니다. 추가 분석 중 4편의 원문 검토를 마쳐 현재 총 112편이며, 96편이 남았습니다. 이 README는 완료된 분석만 집계합니다.

- [논문 목록·출처](research/CORPUS.md) · [분포와 한계](research/COVERAGE-AUDIT.md)
- [논문 간 종합](research/SYNTHESIS.md) · [스킬용 근거 인덱스](skills/hci-academic-writing/references/corpus-index.md)
- [길이 측정](research/measurements/README.md): 본문·섹션 7편, 선택 문단 32개/14편
- [계획](docs/PLAN.md) · [표집 결정](docs/SAMPLING-PLAN.md) · [단계별 검토](docs/REVIEW-LOG.md)

분석은 AI 에이전트가 작성하고 통합 과정에서 검토했습니다. 독립적인 사람 코더의 검증은 수행하지 않았습니다. 길이를 수치로 측정한 범위는 위 부분집합이며, 보편적인 적정 문단 길이나 섹션 비율을 주장하지 않습니다.

## 검증 결과와 한계

설치·LaTeX 검사기 자동 테스트 18개가 통과했습니다. 기록된 로컬 원문 버전으로 길이 측정을 재현했습니다. 실제 Claude Code 편집 2건에서는 설치된 스킬을 읽고, 무관한 파일과 제공된 근거를 보존했으며 ACM LaTeX 컴파일도 통과했습니다. [파일 편집 검증 기록](tests/behavior/README.md)에 환경과 범위를 명시했습니다.

생성 실험에서는 지침을 제공했어도 관찰 기간, 코딩 단위, 연구 공백에 관한 미확인 주장을 추가하는 오류가 남았습니다. [오류와 수정 기록](tests/behavior/SEMANTIC-REPORT.md)을 공개합니다. 이 도구는 작성을 돕지만 사실성·방법론적 타당성·게재 성과를 보장하지 않습니다. 대조 실험이나 독립적인 연구자 사용 평가는 아직 수행하지 않았습니다.

```sh
python3 -m unittest discover -s tests/install -v
python3 -m unittest discover -s tests/latex-audit -v
python3 scripts/build_corpus_index.py --check
```
