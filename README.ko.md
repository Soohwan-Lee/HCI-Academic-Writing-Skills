# HCI Academic Writing Skills

**논증을 세우고, 논문을 구성하고, 문장을 다듬습니다.**

HCI 논문 폴더에서 작업하는 AI 코딩 에이전트를 위한 라이팅 스킬입니다. 연구 자료를 바탕으로 기여에 맞는 개요를 구성하고, 섹션과 문단을 발전시키며, Overleaf에 업로드할 실제 LaTeX 파일을 수정하도록 돕습니다.

**CHI, CSCW, UIST, DIS, IUI**에 제출하는 시스템, 실증 연구, 사회기술적 현상 분석, Research through Design, 개념 연구, 문헌 리뷰 등 다양한 논문을 대상으로 합니다.

## 무엇을 도와주나요?

연구 자료, 초안, 작업 요청은 연구자가 제공합니다. 스킬은 근거를 논문으로 발전시키는 데 필요한 지침과 라이팅 참고 자료를 에이전트에 제공합니다. 작업에 필요한 자료만 선택적으로 읽도록 구성되어 있습니다.

| 연구자의 요청 | 에이전트가 작성하도록 안내하는 결과물 |
|---|---|
| “이 논문의 기여를 명확하게 해줘.” | 무엇을 새롭게 알게 하는지, 어떤 근거가 뒷받침하는지, 어디까지 주장할 수 있는지 |
| “어떤 순서로 구성해야 할까?” | 섹션·하위섹션 순서와 문단별 역할, 논리적 연결을 포함한 개요 |
| “이 자료로 섹션을 작성해줘.” | 제공된 근거에 기반한 원고와 아직 필요한 사실의 명시 |
| “Related work가 논문 나열처럼 보여.” | 연구 문제와 기존 접근 간 관계를 중심으로 구성한 문헌 종합 |
| “문단과 문장이 잘 연결되지 않아.” | 문단 순서, 문장 간 연결, 지시 대상이 명확해진 원고 |
| “분량을 줄여줘.” | 핵심 주장, 근거, 불확실성을 유지한 압축 문안 |
| “리뷰 의견에 대응해줘.” | 근거와 실제 원고 수정에 연결된 답변 |

보통 결과물은 **원고 파일의 수정과 변경 이유에 대한 짧은 설명**입니다. 문장 하나를 다듬는 요청에 논문 전체의 계획 수립을 요구하지 않습니다.

## 기여에 따라 논문의 구조가 달라집니다

인터뷰는 시스템 설계에 필요한 요구를 찾을 수도, 사회기술적 현상을 해석할 수도, 새로운 개념을 발전시킬 수도 있습니다. 방법이나 제출 학회가 같더라도 논증의 구조는 달라집니다.

이 스킬은 **기여, 연구 방법, 주제, 학회, 원고 형식**을 구분하고, 다음 네 수준을 연결해 글을 계획합니다.

> **섹션:** 독자가 여기서 무엇을 이해해야 하는가?
>
> **하위섹션:** 어떤 질문에 어떤 순서로 답해야 하는가?
>
> **문단:** 어떤 주장이나 질문을 어떤 자료로 발전시키는가?
>
> **문장:** 이미 제시한 정보에서 다음 추론으로 어떻게 이어지는가?

실제 논문에서 분석한 구조에는 다음과 같은 대안이 있습니다.

| 논증의 성격 | 가능한 전개 예시 |
|---|---|
| 새로운 인터랙션 역량 | 기능 개요 → 설계 근거 → 구현 → 역량별 평가 |
| Formative inquiry에 기반한 시스템 | 탐색적 조사 결과 → 설계 방향 → 시스템 → 서로 다른 평가 질문 |
| 성찰적 디자인 / pictorial | 상황과 실천 → 성찰의 관점 → 재료·시각적 사례 → 사례 간 해석 |
| 사회기술적 이해 | 상황에 놓인 경험 → 관계와 긴장 → 개념적 해석 → 함의 |
| 역사적 탐구 | 시대별 서술 → 시대를 가로지르는 분석 차원 → 함의와 방법론적 성찰 |
| 개념 개발 | 개념의 계보 → 탐색용 디자인 → 참여자의 해석 → 개념적 논의 |
| 데이터셋·연구 자원 | 구축 → 특성 분석 → 과제별 활용 검증 → 재사용 조건 |
| 해석적 문헌 리뷰 | 선정과 분석 → 주제별 결과 → 개념적 종합 → 후속 연구 의제 |

학회별 필수 템플릿이 아니라, 논증의 목적에 따라 선택할 수 있는 구조입니다. [구조 가이드](skills/hci-academic-writing/references/architectures.md)는 각 구조가 언제 도움이 되는지 설명합니다. [기여 유형 목록](skills/hci-academic-writing/references/contribution-catalogue.md)은 참여적 변화, 비판, 방법론, 재현 연구, 복합 기여도 다룹니다.

공통 자료는 abstract, introduction, research gap 중심의 related work, discussion, 문단 전개와 문장 연결을 다룹니다. 두괄식은 주장을 바로 이해할 수 있을 때 유용하지만, 서사나 뒤늦게 드러나는 해석이 필요한 문단도 있습니다. 8,000단어 기준의 분량 배분은 계획을 돕는 참고안이며, HCI 논문 전체에 적용되는 규칙은 아닙니다.

## 빠른 시작

기존 논문 폴더, 지원되는 AI 코딩 에이전트, 설치 스크립트를 실행할 **Python 3.9 이상**이 필요합니다. 별도의 Python 패키지는 필요하지 않습니다. 이 저장소는 스킬 묶음을 제공하며, 모델과 파일 편집 기능은 사용하는 에이전트가 제공합니다.

### 1. 저장소 받기

```sh
git clone https://github.com/Soohwan-Lee/HCI-Academic-Writing-Skills.git
cd HCI-Academic-Writing-Skills
```

### 2. 논문 폴더에 설치하기

`/path/to/paper`를 ACM 프로젝트가 있는 폴더로 바꾸고 사용하는 에이전트를 선택합니다.

```sh
# Codex 설치 미리보기: 파일을 쓰지 않습니다.
python3 scripts/install_skill.py --host codex --scope project --project-root /path/to/paper

# Codex용 설치
python3 scripts/install_skill.py --host codex --scope project --project-root /path/to/paper --apply

# 또는 Claude Code용 설치
python3 scripts/install_skill.py --host claude-code --scope project --project-root /path/to/paper --apply
```

Antigravity는 `--host antigravity-app`, `antigravity-ide`, `antigravity-cli` 중 사용하는 환경을 선택합니다. 프로젝트 설치 위치는 Codex·Antigravity의 경우 `.agents/skills/hci-academic-writing/`, Claude Code의 경우 `.claude/skills/hci-academic-writing/`입니다.

설치기는 기본적으로 미리보기만 수행하고, 기존 파일과 충돌하면 덮어쓰지 않습니다. 이전 버전을 업데이트하려면 기존 설치본을 검토하고 다른 곳으로 옮긴 뒤 다시 설치하세요. 개인용 설치, 정확한 경로, 검증 범위는 [설치·호환성 문서](docs/COMPATIBILITY.md)에 있습니다.

### 3. 논문 폴더를 열고 스킬 사용 요청하기

**라이팅 스킬 저장소가 아니라 논문 프로젝트 폴더에서** 새 에이전트 세션을 시작합니다. `hci-academic-writing`을 명시하고, 해당 `SKILL.md`를 읽었는지 확인합니다.

> hci-academic-writing을 사용해. 루트 파일은 main.tex야. sections/related-work.tex를 읽고 아직 해결되지 않은 연구 문제를 중심으로 재구성해. 기존 주장과 인용의 연결은 유지해. 문단 순서와 문장 간 흐름을 개선해서 파일을 수정하고, 변경 사항을 요약해.

기존 원고 구조는 그대로 사용합니다.

```text
my-paper/
├── main.tex
├── sections/
│   ├── introduction.tex
│   ├── related-work.tex
│   └── ...
├── references.bib
└── .claude/skills/hci-academic-writing/  # Codex는 .agents/skills/
    ├── SKILL.md
    ├── references/
    └── scripts/
```

설치된 묶음만으로 스킬을 사용할 수 있습니다. 전체 논문 분석 자료나 Zotero 라이브러리는 필요하지 않습니다. 컴파일에는 TeX 도구가 필요하며, Overleaf 업로드는 별도 작업입니다. ACM 템플릿은 포함되어 있지 않습니다.

## 내 원고에 적용하기

루트 파일, 수정 범위, 사용할 근거, 분량 제한을 알려주세요. 제출 형식을 다룰 때는 학회·트랙과 공식 요구사항도 함께 제공합니다.

### 큰 제목만 나열하지 않는 개요 만들기

> hci-academic-writing을 사용해. main.tex와 연구 노트를 읽고 중심 기여를 파악해서 적합한 개요를 제안해. 각 섹션의 목적과 하위섹션 순서를 적어줘. 핵심 섹션은 문단별 주장, 뒷받침할 자료, 다음 문단으로 이어지는 이유까지 계획해. 개요를 수정하기 전에 중요한 대안 구조가 있다면 차이를 설명해.

### 연구 결과를 해석적 논의로 발전시키기

> hci-academic-writing을 사용해. 제공한 인터뷰 분석 결과로 sections/discussion.tex를 작성해. 관찰한 관계가 앞서 소개한 개념을 어떻게 확장하거나 복잡하게 만드는지 설명해. 참여자의 경험, 우리의 해석, 제안하는 함의를 구분해. 모든 결과를 시스템 요구사항으로 바꾸지는 마.

### 디자인 연구의 논증 구성하기

> hci-academic-writing을 사용해. 디자인 일지와 주석이 달린 산출물 이미지를 읽고, 만들기와 성찰에서 무엇을 배웠는지를 중심으로 RtD 논증을 구성해. 재료와의 만남이 디자인 이해로 이어지도록 하위섹션과 문단 역할을 제안해. 긴장과 해결되지 않은 해석도 포함해.

### 문헌 리뷰의 종합 구성하기

> hci-academic-writing을 사용해. 리뷰 프로토콜과 논문별 추출표로 결과·종합 섹션을 계획해. 수집한 문헌의 특성과 논문들을 가로지르는 해석을 구분해. 실제 리뷰 목적과 절차에 맞는 구조를 선택하고, 무조건 systematic review라고 가정하지 마.

### 문단 수정·압축하기

> hci-academic-writing을 사용해. sections/results.tex의 선택한 문단을 150단어 이내로 수정해. 추정치, 불확실성, 유의하지 않은 결과, 분석 단위를 유지해. 단어 수를 센 기준과 의미 있는 변경 사항을 알려줘.

위 내용은 사용 요청 예시이며, 성능 향상을 측정한 결과가 아닙니다. 에이전트는 인용 키, label, macro와 관련 없는 수정 사항을 보존하도록 안내됩니다. 알 수 없는 사실은 그럴듯한 문장으로 채우지 않고 `% HCI-TODO[evidence]: ...` 같은 초안 주석에 남기도록 합니다.

## 어떤 분석을 바탕으로 만들었나요?

**본문을 분석한 논문 노트 128편**이 있습니다. CHI 41편, CSCW 25편, UIST 18편, DIS 21편, IUI 21편과 COMPASS·Findings of EMNLP 각 1편입니다. 수상 논문, 축적된 연구 계보, 서로 다른 연구 형식을 포함하며, 수상 여부의 근거는 라이팅 분석과 별도로 기록합니다.

이 중 **12개 심층 구조 맵**은 실제 섹션·하위섹션 순서와 선택한 구간의 전체 문단 전개, 문장별 흐름을 추적합니다. 관찰한 구조를 조건별 작성 지침에 연결한 자료입니다. 128편의 모든 문단을 이 깊이로 분석했다는 의미는 아닙니다.

| 근거 | 확인할 자료 |
|---|---|
| 논문 선정, 출처, 분석 노트 | [코퍼스](research/CORPUS.md) · [범위 점검](research/COVERAGE-AUDIT.md) |
| 계층 구조, 문단 역할, 문장 흐름 | [구조 맵](research/structure-maps/README.md) |
| 논문 간 종합 | [분석 종합](research/SYNTHESIS.md) · [스킬 내 논문 색인](skills/hci-academic-writing/references/corpus-index.md) |
| 분량의 정량 관찰 | [측정 자료](research/measurements/README.md): 본문·섹션 사례 7편, 14편에서 선택한 문단 32개 |
| 결정과 수정 과정 | [현재 계획](docs/STRUCTURE-ANALYSIS-PLAN.md) · [검토 기록](docs/REVIEW-LOG.md) |

교육적 목적에 따라 선정한 사례 모음이며, AI를 활용해 분석하고 통합 과정에서 검토했습니다. 대표 표본이나 독립적인 사람의 코딩으로 검증한 연구는 아닙니다. 문단 길이와 섹션 비율을 확정된 규범으로 제시하지 않습니다. 새 논문은 편수를 채우기보다 중요한 빈틈을 해결할 때 추가합니다.

## 어디까지 검증했나요?

| 구분 | 현재 근거 |
|---|---|
| 설치·LaTeX 어휘 수준 점검 | 자동 테스트 18개, 격리된 폴더에서 호스트별 설치 경로 검증 |
| Claude Code 파일 편집 | 여러 파일로 구성된 ACM 테스트 원고에서 제한된 수정 2건 수행, 명시적 스킬 로딩과 컴파일 성공 |
| Codex·Antigravity 실제 편집 | 아직 검증하지 않음 |
| 스킬 자동 발견 | 제한된 Claude 테스트에서 확인하지 못함. 이름을 명시한 요청은 검증함 |
| 논문 전체의 구조적 작성 품질 | 기여별 개요·섹션 작성 검증을 더 수행해야 함 |

[파일 편집 보고서](tests/behavior/README.md)에 실제 동작을 기록했습니다. 다른 생성 실험에서는 근거 없는 주장이 나타났으며, [의미 검토 보고서](tests/behavior/SEMANTIC-REPORT.md)에 실패와 수정을 남겼습니다. 저자로서 에이전트의 변경 내용을 검토해야 합니다. 출판 성과나 전반적인 글쓰기 품질 향상을 입증한 대조 실험은 없습니다.

지금 사용할 수 있는 스킬이며, 분석의 깊이와 검증을 계속 보강하고 있습니다.

1. 특히 RtD, 실증 연구, 리뷰에서 **같은 기여 유형 안의 서로 다른 전개 방식**을 더 비교합니다.
2. 여러 파일로 구성된 ACM 프로젝트에서 개요 선택, 섹션 작성, 문단 재구성을 검증합니다.
3. 비교 가능한 분량 측정을 늘린 뒤 정량적 지침을 보강합니다.
4. 일반적인 사용자 세션에서 호스트별 스킬 발견과 실제 편집을 확인합니다.

진행 기준은 [현재 계획](docs/STRUCTURE-ANALYSIS-PLAN.md)에 기록합니다. 128편을 200편으로 늘리는 것은 완료 조건이 아닙니다.

## 기여와 재사용

분석 오류 수정, 대비되는 좋은 사례, 실제 집필에서 발견한 실패 사례를 환영합니다. [기여 안내](CONTRIBUTING.md)를 참고하세요.

프로젝트에서 작성한 코드와 문서는 [MIT 라이선스](LICENSE)로 제공합니다. 연결된 논문의 권리는 각 원저작물에 있습니다. 원문 PDF, 개인 Zotero 기록, 모델 대화 원문은 배포하지 않습니다. 표지와 로고는 [시각 자료 출처](assets/README.md)에 설명되어 있습니다.

로컬 검증 명령:

```sh
python3 -m unittest discover -s tests/install -v
python3 -m unittest discover -s tests/latex-audit -v
python3 scripts/build_corpus_index.py --check
```
